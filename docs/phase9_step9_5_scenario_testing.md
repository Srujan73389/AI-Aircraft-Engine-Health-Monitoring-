## 3. Temporal Persistence Filtering Architecture

To prevent transient sensor spikes, electromagnetic interference (EMI), or momentary telemetry dropouts from triggering unwarranted maintenance actions or flight line alerts, the system enforces a multi-cycle temporal persistence filter:

$$\text{Persistent Alarm} \iff \sum_{t - k + 1}^{t} \mathbb{I}(\text{Anomaly}_t) \ge K_{\text{persist}} \quad (K_{\text{persist}} = 3)$$

### Transient Noise Suppression vs Sustained Failure Locking
1. **Single-Cycle Noise Spikes (SCEN-03):**
   - When an isolated sensor spike triggers statistical threshold breaches ($\text{score}_{IF} > \tau_{IF}$ or $\text{score}_{PCA} > \tau_{PCA}$), `consecutive_breaches` is evaluated as $1 < K_{\text{persist}}$.
   - Severity is constrained to `"CAUTION"` and `persistence_alarm` remains `False`.
   - The user interface highlights the anomaly without sounding maintenance lockouts or dispatch halts.
2. **Sustained Multi-Cycle Degradation (SCEN-04):**
   - When anomalies persist across $k \ge 3$ consecutive operating cycles, the persistence gate trips.
   - Severity transitions to `"CRITICAL"` and `persistence_alarm` is latched to `True`.
   - Immediate inspection workflows are recommended.
